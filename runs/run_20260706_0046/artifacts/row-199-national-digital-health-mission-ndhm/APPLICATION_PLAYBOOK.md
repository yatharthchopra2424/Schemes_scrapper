# Application Playbook

## How to Use This File
For each new client case, assign it a Case ID, pick the target scheme, and follow the steps below.

---

## Stage 1: Eligibility Verification (Day 1–3)

### Checklist
- [ ] **Citizens/Individuals**: Eligible to generate a unique Ayushman Bharat Health Account (ABHA) number. No restrictions on age, turnover, or business registration.
- [ ] **Health Facilities (Public & Private)**: Eligible to register on the Health Facility Registry (HFR) across all systems of medicine (modern, Ayurveda, Yoga, Naturopathy, Unani, Siddha, Homoeopathy). Must provide facility name, location, operational status, services offered, ownership details.
- [ ] **Healthcare Professionals**: Eligible to register on the Healthcare Professionals Registry (HPR) across all systems of medicine (doctors, nurses, paramedics, allied health workers). Must provide professional details and credentials.
- [ ] **Health Tech Companies**: Eligible to engage with ABDM to integrate and validate software systems with ABDM APIs via the ABDM Sandbox. Must have software capable of integration with ABDM components.
- [ ] **State Governments & Health Authorities**: Eligible to adopt ABDM to improve healthcare services. Must refer to technical guidelines and adoption resources.
- [ ] **Voluntary Participation**: Participation in the National Digital Health Ecosystem (NDHE) is purely voluntary; no mandatory enrollment required.
- [ ] **Aadhaar Requirement**: Aadhaar ID is required for ABHA, HPR, and HFR registration (for identity verification via OTP).
- [ ] **Mobile Number**: Mobile number linked to Aadhaar is required for OTP verification during registration.
- [ ] **No Financial Eligibility**: The scheme does not provide direct financial support; eligibility is not based on income, turnover, or employee count.
- [ ] **No Sector or Turnover Thresholds**: Open to all sectors within healthcare ecosystem; no minimum turnover or employee requirements.
- [ ] **Geographic Scope**: Pan-India; available to all states and union territories.
- [ ] **Age of Business**: Not applicable; individuals and entities can register regardless of establishment date.

**Sources**:  
- Scheme Key Facts: Eligibility, Target Beneficiaries, Required Documents  
- Supporting Evidence: https://abdm.gov.in/citizens, https://abdm.gov.in/health-facilities, https://abdm.gov.in/healthcare-professionals, https://abdm.gov.in/health-tech-companies, https://abdm.gov.in/for-states  
- Application Portal: https://abha.abdm.gov.in/register (for ABHA), https://facility.abdm.gov.in/ (for HFR), https://hpr.abdm.gov.in/en (for HPR), https://sandbox.abdm.gov.in/ (for health tech), https://dashboard.abdm.gov.in/abdm/ (for states)

## Stage 2: Document Collection (Day 3–10)

### Universal Documents (always required)
- Aadhaar ID (mandatory for ABHA, HPR, HFR registration)
- Mobile number linked to Aadhaar (for OTP verification)
- Personal details: Name, Year of Birth, Gender, State, District, Email (for ABHA registration)
- Facility name, location, operational status, services offered, ownership details (for HFR registration)
- Healthcare professional details (for HPR registration)
- Credentials to create an account on e-Sushrut Clinic (if applicable)

### Scheme-Specific Documents
- **For ABHA (Citizens)**: Aadhaar ID, mobile number linked to Aadhaar, personal details (name, year of birth, gender, state, district, email)
- **For HFR (Health Facilities)**: Facility name, location, operational status, services offered, ownership details
- **For HPR (Healthcare Professionals)**: Professional details, credentials, Aadhaar-linked mobile number for validation
- **For Health Tech Companies**: Software system details for API integration; no specific documents beyond technical integration proof via sandbox
- **For States**: Strategic overview documents, technical guidelines; no document submission required—adoption is via policy and system integration

### Document Quality Check
- [ ] File size: Ensure documents are clear, legible scans or PDFs (max 5 MB per file recommended)
- [ ] Name matching: Name on Aadhaar must match name provided in registration
- [ ] Mobile number: Must be active and linked to Aadhaar for OTP delivery
- [ ] Email: Valid and accessible for communication and OTP (if email OTP method chosen)
- [ ] Facility/professional details: Must be accurate and verifiable (e.g., address, registration numbers if applicable)
- [ ] Language: Documents can be in English or Hindi; portal supports multiple languages
- [ ] Certification: No notarization or certification required; self-declaration via portal is sufficient
- [ ] Format: PDF, JPEG, or PNG accepted for upload where applicable

## Stage 3: Application Drafting (Day 10–18)

### Project Report / DPR (if required)
- **Not Required**: The ABDM does not require a Detailed Project Report (DPR) or project proposal for registration. It is a voluntary, self-service digital enrollment process.  
- **Note**: Verify with nodal officer only if seeking state-level adoption support or custom integration projects (e.g., for health tech companies pursuing formal partnerships). For standard individual/facility/professional registration, no DPR is needed.  

**Sources**:  
- Scheme Key Facts: Application Process (steps 1–6 are direct portal registrations)  
- Supporting Evidence: https://abha.abdm.gov.in/register, https://facility.abdm.gov.in/, https://hpr.abdm.gov.in/en, https://sandbox.abdm.gov.in/  

### Application Form Filling Protocol
1. **Use Official Portals Only**: Always register via the official ABDM portals (abha.abdm.gov.in, facility.abdm.gov.in, hpr.abdm.gov.in, sandbox.abdm.gov.in) to avoid fraud.  
2. **Aadhaar-Linked Mobile Number**: Ensure the mobile number entered is linked to your Aadhaar for successful OTP delivery.  
3. **Accurate Details**: Enter name, year of birth, gender, state, and district exactly as per Aadhaar to avoid mismatches.  
4. **Consent Declaration**: Explicitly consent to data sharing and processing during ABHA creation; this is mandatory for participation.  
5. **Email (Optional but Recommended)**: Provide a valid email for receiving ABHA number, updates, and consent management notifications.  
6. **Facility/Professional Validation**: For HFR/HPR, ensure facility name, address, and professional credentials are accurate and verifiable.  
7. **Save Reference Number**: Upon successful submission, save the generated reference number or ID (e.g., ABHA number, HFR ID, HPR ID) for future use.  
8. **Portal Language**: Select preferred language (English/Hindi/others) at the top of the portal for ease of use.

## Stage 5: Post-Approval (Day 30–90+)

### Approval Actions
- [ ] **Approval Letter**: Not applicable; registration is instant upon successful OTP verification and form submission. The generated ID (ABHA/HPR/HFR) serves as confirmation.  
- [ ] **Verify Sanctioned Amount**: Not applicable; ABDM does not provide financial grants, loans, or subsidies.  
- [ ] **Utilization Certificate**: Not applicable; no funds are disbursed to beneficiaries.  
- [ ] **Invoice Success Fee**: Not applicable; registration is free of cost.  
- [ ] **Post-Registration Steps**:  
  - For ABHA Holders: Download the ABHA app, link health records, consent to share data with providers, and use ABHA for OPD registration, prescriptions, and lab reports.  
  - For Health Facilities: Ensure ABDM-enabled software integration, display HFR ID prominently, and use ID for interoperable services (e.g., teleconsultation, insurance claims).  
  - For Healthcare Professionals: Use HPR ID to verify credentials, access digital health records (with consent), and participate in ABDM-enabled telemedicine.  
  - For Health Tech Companies: Validate software in ABDM Sandbox, obtain certification, and market ABDM-compliant products.  
  - For States: Monitor adoption via https://dashboard.abdm.gov.in/abdm/, implement ABDM in public health facilities, and use data for policy formulation.  
- [ ] **Client Communication**: Inform client about the voluntary nature of participation, consent management options (to withdraw/share data), and how to update details via the portal.  
- [ ] **Data Privacy Reminder**: Advise client that they can revoke consent for data sharing at any time via the ABHA app or portal, and request data deletion if desired.
